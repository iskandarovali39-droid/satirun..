# SATIRUN — сайт для GitHub Pages

Учебный лендинг бренда спортивной одежды SATIRUN. Создан по маркетинговой презентации бренда и требованиям КТ2 «Подготовить площадку к продвижению».

## Файлы
- `index.html` — адаптивная главная страница, каталог, форма, UTM-захват и заготовка Яндекс.Метрики.
- `privacy.html` — шаблон политики конфиденциальности, который нужно заполнить перед реальным сбором данных.

## Публикация на GitHub Pages
1. Создайте новый публичный репозиторий, например `satirun`.
2. Загрузите `index.html` и `privacy.html` в корень репозитория.
3. Откройте **Settings → Pages**.
4. В разделе **Build and deployment** выберите **Deploy from a branch**.
5. Выберите ветку `main` и папку `/ (root)`, нажмите **Save**.
6. Дождитесь публикации и откройте адрес вида `https://ВАШ-ЛОГИН.github.io/satirun/`.

## Яндекс.Метрика
1. Создайте счётчик для опубликованного адреса сайта.
2. В `index.html` найдите комментарий `00000000` и замените его на числовой ID счётчика, раскомментировав строку `ym(..., "init", ...)`.
3. Проверьте, что визит появляется в отчёте Метрики.
4. Создайте цели, например `lead_submit` и `product_select`, затем раскомментируйте соответствующие `reachGoal` в JavaScript и подставьте ID счётчика.
5. Включите Вебвизор и карту скроллинга в настройках счётчика, если они доступны для выбранной конфигурации.

## UTM-разметка
Сайт сохраняет в `sessionStorage` параметры `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, если посетитель пришёл по размеченной ссылке.

Пример для тестирования (замените домен на опубликованный адрес):

`https://ВАШ-ЛОГИН.github.io/satirun/?utm_source=vk&utm_medium=cpc&utm_campaign=satirun_launch&utm_content=creative_01&utm_term=sportwear`

Сделайте отдельные ссылки для VK, Telegram, коротких видео и других каналов. После тестового перехода проверьте параметры в инструментах разработчика браузера → Application → Session Storage.

## Важно про форму и CRM
GitHub Pages размещает статические файлы и сам по себе не принимает заявки на сервер. Сейчас форма работает в демонстрационном режиме: сохраняет тестовую заявку в `localStorage` текущего браузера и показывает подтверждение. Это не реальная отправка и не интеграция с CRM.

Для полноценного КТ2 подключите серверный endpoint / форму-сервис / CRM-вебхук, передавайте туда поля формы и UTM-метки, а затем проверьте тестовую заявку в CRM. Не размещайте секретные ключи и токены в публичном JavaScript.
